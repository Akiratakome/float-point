\chapter{Introduction}

\section{Context: HRSC Schemes for Discontinuous Compressible Flows}
% <<SECTION_1_BEGIN>>
Compressible-flow simulations are needed when laboratory measurements or exact solutions cannot describe the full evolution of a flow field. In high-speed gas dynamics and aerospace or engineering applications, the solution may contain shocks, contact discontinuities, and rarefactions, so the numerical method must capture sharp waves without replacing them by non-physical oscillations. At the same time, the calculation has to be accurate enough to compare with experiments, exact Riemann solutions, or established benchmark references, while still running in feasible time on available hardware. The longer project also points towards plasma and MHD problems, but the Report 1 evidence is deliberately restricted to Euler validation. Finite-volume high-resolution shock-capturing methods provide the appropriate setting because they evolve conserved cell averages and use Riemann-solver fluxes to handle discontinuous wave interactions \citep{toro2009}. The same features that make HRSC methods useful also make their precision and backend reproducibility worth measuring.
% <<SECTION_1_END>>

\section{Precision and Hardware Reproducibility Problem}
% <<SECTION_2_BEGIN>>
For such schemes, reproducibility is not guaranteed by the statement of the finite-volume algorithm alone. Two runs may use the same reconstruction, Riemann solver, and time step, but differ because binary32 and binary64 round quantities differently, because the compiler fuses operations or reassociates expressions, or because device arithmetic and parallel ordering change the sequence of rounded operations \citep{goldberg_1991,ieee754_2019}. These mechanisms matter in CFD because shock-capturing updates contain branch decisions, limiters, and flux differences near discontinuities, where small arithmetic changes may be amplified rather than remaining isolated roundoff. Recent CFD studies therefore treat reduced or mixed precision as case-dependent: Brogi et al. report OpenFOAM evidence across CFD workloads, while Wang, Xia, and Chen study a heterogeneous hybrid-precision finite-volume method for compressible flow, set against the wider linear-algebra mixed-precision literature surveyed by \citet{higham_mary_2022} \citep{brogi_etal_2024,wang_xia_chen_2025}. These papers motivate validation on the present solver and test matrix; they do not establish that fp32 is adequate here. CUDA, the NVIDIA GPU programming model and backend used in this project, can differ from CPU backends in fp32/fp64 throughput and arithmetic behaviour and can also vary between GPU devices, so this report measures those effects rather than assuming reproducibility across hardware. Verificarlo provides precision diagnostics only: direct fp32 claims use real fp32/fp64 runs; virtual-precision modes should not be treated as IEEE binary32 executions.
% <<SECTION_2_END>>

\section{Report Scope and Contribution}
% <<SECTION_3_BEGIN>>
Report 1 measures how precision and hardware/backend choices affect a Riemann-solver-based HRSC method on a controlled Euler validation suite. The evidence base is Euler ideal-gas validation in one and two space dimensions; MHD motivates the longer project and the direction of Report 2, but no MHD validation is claimed in Report 1. This boundary matters because the same numerical questions arise for ideal-MHD solvers, but the magnetic-field constraint and divergence-control choices require separate validation before they can support conclusions. Within the tested Euler cases in this report, the report contributes selected validation evidence for the stand-alone HRSC solver, quantified fp32/fp64 and matched CPU/GPU saved-output comparisons, and measured sensitivity to selected compiler, solver, and branch-rule variations. The contribution is therefore a bounded baseline for the later project rather than a general statement about all HRSC schemes, all hardware, or untested MHD configurations.
