\chapter{Conclusion}

\section{Aim and Evidence Base}

This report asked how floating-point precision and hardware choice affect a
controlled Euler finite-volume validation harness for shock-dominated HRSC
schemes. The evidence base is intentionally bounded: one-dimensional exact
Riemann tests, two Liska--Wendroff two-dimensional configurations, matched
strict-HLLC CPU/GPU runs, selected compiler and branch-rule variations, and
reference-scaled fp32/fp64 precision comparisons. The results support statements
about these Euler cases and saved output states only; they do not yet validate
MHD extensions, limiter alternatives, or general compiler portability.

\section{Key Findings}

The Euler validation baseline is sound for the tested cases. Sod, Toro3, and
Toro5 reproduce the expected exact Riemann wave ordering, and LW3/LW12 reproduce
the expected interacting two-dimensional shock structures against numerical
references. The measured fp32--fp64 gaps are small relative to the available
reference scale: for example, the LW3
\(R_\rho^{\mathrm{ref}}=
\|\rho_{\mathrm{fp32}}-\rho_{\mathrm{fp64}}\|_1/
\|\rho_{\mathrm{fp64}}-\rho_{\mathrm{ref}}\|_1\) value remains below
\(10^{-4}\) at \(400^2\), while the corresponding LW12 \(R_\rho^{\mathrm{ref}}\) value is
\(1.300607\times10^{-4}\).

Matched CPU/GPU strict-HLLC outputs are byte-identical in the tested saved
states. The original final-time result is now supplemented by intermediate
checkpoints for Sod, LW3, and LW12; across 24 same-precision checkpoint pairs,
the maximum \(L_1/L_\infty/\mathrm{ULP}_{\max}\) drift is \(0/0/0\). This
strengthens the hardware-reproducibility claim, while still leaving internal
stage-by-stage identity and untested platforms outside scope.

The precision conclusion is bounded by the reference scale used in Chapter~5.
The tested fp32 outputs sit below the measured reference-error scale, but this
does not make a general claim that fp32 is sufficient for other cases, fields,
resolutions, final times, or solver choices.

Implementation choices can matter more than nominal precision changes. O2 and
O3 agree bitwise in the tested fp32 compiler mini-matrix, whereas
Ofast+fast-math changes the saved fp32 state, with the largest tested Toro3
drift \(L_1=6.778757\times10^{-5}\). The HLLC--Rusanov comparison is still much
larger, confirming that intentional flux changes dominate the small compiler
and branch-rule drifts in these summaries.

\section{Limitations and Next Step}

The main limitation is scope. The CPU/GPU result is a checkpointed-output
statement, not a proof of identical internal arithmetic. The fp32 compiler
matrix covers only two one-dimensional cases. Limiter sensitivity was not run
because the current harness does not expose a limiter-selection interface
without changing solver numerics.

Report 2 should therefore extend the same evidence discipline rather than
replace it: add an opt-in limiter matrix, broaden compiler and device coverage,
and then move from Euler to validated MHD tests. Until that MHD evidence is
added, the MHD solver remains project context and future direction, not a
validated result of this report.
